# Ebenezer Clone 3.1.29

Release corretiva para GLPI 10.0.x que restaura o modo permissivo de
clonagem solicitado pelo processo operacional e mantém disponível um modo
estrito baseado nas permissões nativas do GLPI.

## Principais correções

- Corrigida a validação CSRF duplicada no endpoint de clonagem.
- Restaurado o modo permissivo para usuários autorizados pelo plugin.
- Mantidas as validações de autenticação, leitura da origem, perfil, entidade,
  categoria, tipo e integridade da requisição.
- Condicionadas as ACLs nativas de categoria, entidade e criação ao modo
  estrito.
- Mantido o comportamento correto durante personificação.
- Impedida a criação de dados parciais quando o modo estrito rejeita a ação.

## Modos de permissão

### Permissões nativas desmarcadas

A autorização configurada no Ebenezer Clone permite criar o chamado sem as
verificações nativas de categoria, entidade e criação.

O GLPI poderá negar a visualização do novo chamado após o redirecionamento.
Nesse caso, a mensagem de sucesso do plugin confirma que o chamado foi criado,
mas o usuário não possui acesso para visualizá-lo.

### Permissões nativas marcadas

Além da autorização do plugin, o GLPI valida:

- acesso à categoria;
- acesso à entidade final;
- direito nativo para criar o chamado.

Se alguma validação falhar, nenhum chamado é criado.

## Compatibilidade

- GLPI: >= 10.0.20 e < 11.0.0
- Diretório do plugin: `ebenezerclone`

## Instalação

1. Baixe o arquivo ZIP ou TAR.GZ nos assets desta release.
2. Extraia a pasta `ebenezerclone` no diretório `plugins` do GLPI.
3. Acesse **Configurar > Plugins**.
4. Instale ou atualize o plugin.
5. Ative o plugin e revise suas configurações.

Não utilize os arquivos automáticos “Source code” gerados pelo GitHub.
